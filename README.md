# midi2tab

ギターのMIDIファイルをASCIIのTAB譜に書き起こすコマンドラインツール。

## セットアップ

```bash
pip install -r requirements.txt
```

## 使い方

```bash
python3 midi2tab.py song.mid --edit          # ブラウザで編集画面を開く(手直し・PDF保存)
python3 midi2tab.py song.mid -o song.pdf     # PDFで出力
python3 midi2tab.py song.mid -o song.html    # HTMLで出力(ブラウザで開く・印刷可)
python3 midi2tab.py song.mid                 # 標準出力にASCIIのTAB譜
python3 midi2tab.py song.mid --list          # トラック一覧(番号・音域)を確認
python3 midi2tab.py song.mid --track 2 --edit         # ギターのトラックだけ使う
python3 midi2tab.py song.mid --tapping -o song.pdf    # H/P/T の奏法記号を推定して付ける
```

HTML出力には、コードネーム・符尾・連桁・付点・3連符・休符・タイ・`let ring`・小節番号・拍子・テンポが入る。

主なオプション:

| オプション | 内容 |
| --- | --- |
| `-o file` / `--format` | `.pdf` / `.html` なら譜面、それ以外はASCII。`--format ascii|html|pdf` で明示も可 |
| `--title` | 譜面のタイトル(既定はファイル名) |
| `--track 1,2` / `--channel 1` | 使うトラック / MIDIチャンネル。既定はドラム(ch10)以外すべて |
| `--tuning dropd` | `standard, dropd, halfdown, dadgad, openg, 7string, bass, ukulele`、または `"D2 A2 D3 G3 B3 E4"` のように低音弦から指定 |
| `--capo 2` | カポ位置(フレット番号はカポからの相対) |
| `--grid 16` | 1マスの音価。`12` で3連8分、`48` で16分と3連の混在。既定は自動判定 |
| `--legato` | 音が切れずにつながる同一弦の単音を H(ハンマリング) / P(プリング) と推定 |
| `--tapping` | 上に加え、左手が届かない音を T(右手タッピング) と推定 |
| `--no-chords` | コードネームの自動判定をやめる |
| `--edit` / `--edits file` | 編集画面を開く / 編集内容の保存先 |
| `--transpose -12` | 半音単位の移調 |
| `--max-fret 20` / `--max-span 4` | 最高フレット / 左手が届くフレット幅 |
| `--width 100` | ASCII出力の1行の最大文字数 |

## 編集画面

`--edit` で `http://127.0.0.1:8765/` に編集画面が開く(`--port` で変更、`--no-open` でブラウザを開かない)。

- 数字をクリック: 別の弦へ移す / 奏法記号(H・P・T、スライド、チョーキング、ビブラートなど)を付ける・外す / コード名を付ける / 音を消す
- コード名をクリック: 名前の変更・削除
- タイトルをクリック: 書き換え
- 上部のバー: チューニング、カポ、グリッド、奏法・コード名の自動判定の切り替え
- 「元に戻す」(Ctrl+Z)、「手直しをリセット」、「PDFで保存」

変更は `song.mid.edits.json` に自動保存され、次回の `--edit` や `-o song.pdf` などの出力にも反映される
(別の場所に保存するには `--edits ファイル名`)。コマンドラインで明示したオプションは保存済みの設定より優先する。

## PDF出力

Chrome / Edge / Chromium のいずれかが入っている必要がある(ヘッドレス印刷を使う)。
自動で見つからない場合は環境変数 `CHROME_PATH` に実行ファイルの場所を指定する。
ブラウザが無い環境では、HTMLを開いて「印刷 → PDFに保存」でも同じ譜面になる。

## しくみ

1. ノートの発音位置をグリッドにクオンタイズし、同時発音を和音にまとめる
2. 和音ごとに押さえられる(弦, フレット)の組み合わせを列挙する
3. 押さえやすさ(フレット幅・ローポジション優先)と左手のポジション移動量をコストにして、
   曲全体で最小になる運指を動的計画法で選ぶ
4. 鳴らしっぱなしで重なる音(アルペジオ)は1つのコードフォームとして別々の弦に割り当てる
5. 音の長さを音符・休符・タイに分解し、ASCIIまたはHTML(SVG)で描画する

## 奏法記号

| 種類 | 記号 | 付け方 |
| --- | --- | --- |
| ハンマリング / プリング | H / P とスラー | `--legato` で推定、または編集画面 |
| タッピング | T | `--tapping` で推定、または編集画面 |
| スライド | 斜線(レガートは `sl.` とスラーつき)、スライドイン / アウト | 編集画面 |
| チョーキング | 矢印と量(¼, ½, full, 1½, 2)。上げて戻す、プリベンドも可 | ピッチベンドから自動、または編集画面 |
| ビブラート / トリル | 波線(トリルは `tr` つき) | ピッチベンド・モジュレーションから自動、または編集画面 |
| パームミュート | `P.M. ---|` | 編集画面 |
| ミュート音 / ゴーストノート | `X` / `(5)` | 編集画面 |
| ハーモニクス | `<12>` N.H. / A.H. / P.H. | 編集画面 |
| トレモロピッキング | 符尾に3本の斜線 | 編集画面 |
| スタッカート / アクセント | 点 / `>` | 編集画面 |
| ピッキング方向 | ダウン / アップの記号 | 編集画面 |
| スラップ / プル | slap / pop | 編集画面 |
| let ring | `let ring ---|` | 音の伸び方から自動 |

MIDIには奏法そのものの情報は入っていない。自動で付くのは、音のつながり方から推定する H/P/T と、
ピッチベンド・モジュレーションの動きから判定するチョーキング・ビブラートだけで、ほかは編集画面で付ける。
ピッチベンドの幅はMIDI内の設定(RPN)を読み、無ければ±2半音とみなす。`--no-expression` で自動判定を止められる。
打ち込みで全ての音がつながっているMIDIでは H/P が付きすぎることがある。

記号の一覧は `examples/techniques.png`。

## コードネームについて

小節 → 半小節 → 1拍の順に区切り、その区間で鳴っている音がコードの型と一致したら名前を付ける。
最低音がルートと違えば分数コード(`C/G`)。経過音を含むメロディや2音だけの区間には付かない。
同じ構成音で複数の呼び方があるもの(Am7 と C6 など)は最低音で決める。

## 現在の制限

- リズムは単旋律として書く(各音は次の発音まで。伸ばす音は `let ring` で示す)
- アーム(ワーミーバー)、装飾音、ストロークの矢印、ラスゲアードは未対応
- 奏法記号は音(和音はまとめて)単位で付く。和音の中の1音だけには付けられない
- 曲中のテンポ変更は表示しない(最初のテンポのみ)
- 音域外の音はオクターブ移動、同時に押さえられない音は内声から省略し、件数を警告表示
